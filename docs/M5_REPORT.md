# Proto Engine — M5

Дата: 2026-09-08. Windows x64, GCC 16.2.0, Vulkan 1.3, Intel Arc 140T.

## Реалізовано

- Публічні C++20-заголовки SDK, статичні бібліотеки, CMake package, ідентифікатор
  збірки та зафіксовані прапорці/компілятор. Публічні заголовки не включають
  Vulkan, ImGui, glTF-імпортер або JSON-бібліотеку.
- Явна реєстрація стабільних BehaviorTypeId, кілька прив'язок на об'єкті,
  OnStart/OnUpdate/OnStop. Вісім типів параметрів із defaults/ranges та збереженням
  невідомих полів. EntityRef/AssetRef перевіряються разом зі значеннями за замовчуванням.
- Компіляція Code у власний Player проєкту. Помилки мають шлях, рядок і колонку;
  файл відкривається в нижній панелі C++. Збереження коду узгоджене з Undo/Redo,
  переміщенням файлів та зовнішніми змінами.
- Окремий режим describe без створення вікна/GPU та викликів життєвого циклу.
  Отримана схема залишається доступною для виправлення сцени, навіть коли її
  невірні параметри блокують запуск.
- Play копіює поточну сцену, включно з незбереженими правками, у приватний snapshot.
  Матеріали та модельні ресурси зберігаються як спільні blobs із SHA-256; відкриті
  handles забороняють їх зміну/видалення до завершення процесу.
- Player використовує спільний Vulkan-рендерер з PBR і динамічними тінями;
  редакторський інтерфейс та glTF-імпортер до нього не лінкуються.
- Під час Play 3D-рендеринг редактора призупиняється. Журнал, Stop і окремі CPU/RAM
  метрики залишаються доступними. Stop спочатку кооперативний, потім завершує
  завислий процес та його дочірні процеси.
- Приклад [Proto Playground](../examples/ProtoPlayground/Launch-Playground.cmd):
  Spin, MoveLight і KeyboardMove; WASD/стрілки та Space у вікні Player.

## Перевірки

Повний CTest: **24/24 Debug (193,65 с)** та **24/24 Release (149,22 с)**.
Після фінальних виправлень повторено змінені M5 сценарії: **3/3 Debug (75,90 с)**
та **3/3 Release (61,42 с)** — процеси, реальна C++-збірка та нативний Play.
Остаточні результати й SHA-256: [m5-summary.json](research/m5-summary.json).

Перевіряються структура й roundtrip усіх типів, цілі числа за межами 2^53,
невідомі типи, відсутні посилання, Undo/Save As, копіювання typed AssetRef,
ресурси без екземплярів у сцені, порядок callbacks та ізоляція помилок.
Сцени з 10 000 об'єктів перевіряються з поведінками й без них.

Процесні тести перевіряють аргументи з Unicode/пробілами/лапками, stderr,
безперервний потік виводу, stop event, аварії, зависання, завершення дочірніх
процесів, коротке очікування з повторним опитуванням та збій призначення Job Object.

Зовнішній CMake consumer справді компілюється зі встановленого SDK та його
перенесеної копії. Перевіряються діагностики, помилкова збірка, скасування,
повторний запуск, виняток/зависання describe, несумісний SDK і сторонні CXXFLAGS.
Застарілий executable не видається за результат невдалої збірки.

Фінальний прогін виявив зависання стандартного очищення тимчасового дерева з
269-символьним шляхом до object-файла. Для внутрішніх build snapshots і тестових
папок додано нативне Win32-очищення з підтримкою довгих шляхів. Воно не переходить
за junction/reparse points та повертає помилку без нескінченного повторення.
[Окрема перевірка](research/m5-long-path-probe.txt) підтвердила видалення файла зі
шляхом у 402 символи, цілісність сусіднього файла та цілі junction, швидку відмову
на заблокованому файлі й успішне повторення після його закриття.

Нативний редакторський сценарій запускає власний скомпільований Player і перевіряє:
рух/обертання, клавіатуру, перерахунок тіней, паузу редактора, помилку компіляції,
аварію, зависання та повторний запуск. Сцена, dirty state, вибір і Undo залишаються
ідентичними стану перед Play. Для 90 кадрів зафіксовано 3 OnStart, 270 OnUpdate,
3 OnStop та 1350 shadow-face passes; Vulkan validation errors — 0.

Додаткові нативні сценарії перевіряють кнопку збереження коду та Undo, оновлення
активного текстового поля після зовнішнього редагування і відновлення після
неправильного EntityRef. Debug використовує core + synchronization validation;
Release працює без validation layer. Збережено [кадр Player](research/m5-player.png)
та [кадр редактора](research/m5-editor.png).

PE-імпорти Release Player містять тільки системні Windows DLL. Перевірка символів
не виявила ImGui, GltfImporter або AssetWorkspace. Це перевірка складу поточного
Player на цьому ПК; переносимість повного пакета належить до M6.

## Витрати ресурсів

SDK-записи трансформацій групуються до кінця кадру або запиту світової позиції.
Окремий Release-мікротест: 1000 об'єктів, два записи на кожен, 10 кадрів,
три повтори, без рендерингу.

| Спосіб оновлення | Медіана, мс/кадр |
| --- | ---: |
| Окремий повний прохід сцени після кожного запису | 23,4828 |
| Групове оновлення | 0,3309 |

Це порівняння підсистеми трансформацій, а не FPS цілого рушія. Пошук конфліктів
BehaviorBindingId використовує індекс; додавання об'єкта не сканує всі попередні.
Файловий вміст Code та зібрані результати прив'язані до ключа; повторна перевірка
опису поведінок залишається обов'язковою.

## Межі та наступний етап

M5 Play використовує внутрішній manifest у .proto/snapshots. Переносимий output-пакет,
additionalAssets та налаштування графіки у Player — M6. Немає фізики,
ray tracing, hot reload DLL або ізоляції довільного C++ коду від ОС.
Перевірки проведено на цьому ПК; запуск на іншому чистому Windows ще не перевірявся.

M4 executable збережено без змін SHA-256. Використано Luna/max для реалізації
окремих частин та незалежного Astra/max для перевірки.

## Технічні джерела

Політика CMake module scanning звірена з
[CXX_SCAN_FOR_MODULES](https://cmake.org/cmake/help/latest/prop_tgt/CXX_SCAN_FOR_MODULES.html).
Правила абсолютних довгих шляхів звірені з
[Maximum Path Length Limitation](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation).
Завершення дерева використовує
[TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject)
та очікування сигналу процесних об'єктів, описане у
[Terminating a Process](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-process).

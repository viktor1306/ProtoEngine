# M8 — приймання v0.1

Дата: 2026-09-09. **M8 прийнято: v0.1 пройшла погоджений цикл.**
Фінальні збірки мають **43/43 успішні перевірки Debug та 43/43 Release**.
Комплект для роботи — `dist/ProtoEngine-v0.1`; запуск і керування описані
у [M8_GUIDE.md](M8_GUIDE.md).

## Реалізація

Новий native сценарій редактора створює проєкт і послідовно проходить імпорт,
ієрархію, файлову історію, повторне відкриття, C++/Play/Stop та експорт.
`ProtoProject` надає стартовому шаблону штатне створення з новими UUID
та відмовою перезаписувати наявну папку.

Комплект має відносну структуру `bin`/`sdk`, authored-демонстрацію,
окремий готовий Player, інструкції й ліцензії. SHA-256 manifest фіксує склад
поставки. Подробиці критеріїв: [M8_CONTRACT.md](M8_CONTRACT.md).

Під час приймання виправлено дві проблеми запуску:

- Компіляція з перенесеного SDK знаходить `as`/`ld` у каталозі обраного GCC,
  навіть якщо в батьківському PATH є лише Windows System32. Шлях додається
  тільки до дочірніх configure/build-процесів; батьківський PATH перевіряється на незмінність.
- Пошук Vulkan validation layer використовує наявний короткий Windows-шлях,
  якщо він доступний. На цьому NTFS це дозволяє запуск із перенесеної папки
  з українськими літерами. У Debug validation явно перевіряється також у Player.

вибір об'єкта й історія редактора збережені. Детальні перевірки динамічних
тіней, MASK, переповнення shadow pool і падіння/примусового завершення Player
входять до повної регресії M3/M5/M6/M7.

[Машинний підсумок](research/m8-summary.json) містить SDK build IDs і хеші
фінальних бінарних файлів. [Перевірка збереження M7](research/m8-preservation.json)
підтверджує незмінність його чотирьох перевірених Editor/Player бінарних файлів,
рендерера та шейдерів. У Player bootstrap змінений лише пошук validation layer.

До комплекту входять Editor/SDK, генератор стартового проєкту, authored-демо
з C++-камерою, готова папка Player, інструкції, звіти та ліцензії.
Кеш проєкту `.proto`, компілятор і Python до нього не копіюються.

## Продуктивність та обмеження

M8 використовує рендерер M7 без зміни шейдерів або алгоритмів світла.
[M7_REPORT.md](M7_REPORT.md) містить вимірювання порожньої, малої та великих
сцен, CPU/GPU frame time, пам'ять, завантаження ресурсів і контрольні A/A-прогони.
Загальне прискорення GPU/FPS не встановлено; погіршення окремих сцен збережено
у звіті. M8 не вводить нових тверджень про швидкодію на підставі коротких перевірок.

Перевірка стосується цього Windows x64 ПК (Core Ultra 7 255H, Intel Arc 140T,
приблизно 64 ГБ RAM). Інше обладнання не сертифіковане. SDK має точну версію
GCC і шляхи наявних інструментів; перенесення готового Player не має цих
залежностей. Другий Python і компілятор у комплект не додаються.

Підтримка довільних authored-шляхів понад MAX_PATH не завершена: надто довга
папка разом із тимчасовим суфіксом завадила створенню тестового проєкту.
Службову вкладеність стенду скорочено; Unicode та пробіли у шляхах залишено.
Для роботи рекомендовано коротку папку проєкту. Завантаження Debug validation
із не-ASCII шляхів залежить від наявності придатного короткого alias; на томах
без нього може знадобитися латинський шлях до діагностичного комплекту.
Растрові тіні можуть мати дискретність та артефакти self-shadowing; результат
залежить від resolution, filter, bias та кута світла.

Підготовка сцени/частини операцій у наскрізному тесті виконується через
програмні сервіси. Native-події перевіряють конкретні UI-контракти, зазначені
у JSON. Це не запис ручного проходження кожного діалогу.

Ray tracing, BLEND/скло, фізика/зіткнення та імпортована/скелетна анімація
залишаються поза v0.1. Інструкція роботи: [M8_GUIDE.md](M8_GUIDE.md).

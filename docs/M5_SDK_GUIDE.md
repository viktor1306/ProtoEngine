# C++ SDK та Play

SDK використовує встановлений GCC/w64devkit і C++20. Додатковий Python не потрібен.
Пакет для поточної конфігурації лежить у `build/m5-debug/sdk` або `build/m5-release/sdk`.
Звичайна збірка рушія також збирає та встановлює цей локальний пакет.

## Перший запуск

1. Відкрийте [Proto Playground](../examples/ProtoPlayground/Launch-Playground.cmd).
2. Натисніть **Play**. З'явиться окреме вікно Player: куб обертається, лампа рухається,
   **WASD / стрілки** переміщують куб, **Space** піднімає його.
3. Натисніть **Stop** у редакторі або **Escape** у Player.
4. Виберіть куб чи лампу, прокрутіть інспектор до **Поведінки** та змініть параметри.
   Play візьме поточні значення, включно з незбереженими змінами сцени.

Подвійний клік на файлі в `Code` відкриває нижню панель C++. Збережіть код кнопкою
або Ctrl+S у цій панелі, потім натисніть **Зібрати C++**. Клік на діагностиці у
журналі відкриває файл і виділяє відповідний рядок. Схеми класів оновлюються після
компіляції. У розділі **Поведінки** можна прикріплювати кілька класів до одного об'єкта.

## Мінімальна поведінка

```cpp
#include <Proto/Behavior.hpp>

class Move final : public proto::sdk::Behavior {
    void OnUpdate(proto::sdk::BehaviorContext& context, double dt) override {
        auto transform = context.GetTransform(context.Self());
        transform.position.x += float(context.Property<double>("speed") * dt);
        context.SetTransform(context.Self(), transform);
    }
};

void RegisterProjectBehaviors(proto::sdk::BehaviorRegistry& registry) {
    registry.Add<Move>({
        proto::BehaviorTypeId::parse("60000000-0000-4000-8000-000000000001"),
        "Move",
        {{"speed", proto::sdk::PropertyType::Float, 1.0, -20.0, 20.0, "Швидкість, м/с"}}
    });
}
```

Прикріпіть Move до потрібного об'єкта. Для нового класу створіть власний UUID;
збережіть його при перейменуванні класу. Функція реєстрації визначається один раз
на проєкт. Нові проєкти вже містять її порожній шаблон. Старі файли M4 автоматично
не переписуються: коментар-заглушку можна замінити цим шаблоном.

## Доступні значення

| Тип схеми | Тип C++ у Property |
| --- | --- |
| Bool | bool |
| Integer | int64_t |
| Float | double |
| String | std::string |
| Vec3 | proto::sdk::Vec3 |
| Color | proto::sdk::Color |
| EntityRef | proto::sdk::EntityRef |
| AssetRef | proto::sdk::AssetRef |

Опис поля містить стабільне ім'я, тип, значення за замовчуванням та необов'язкові
min/max/label. Імена полів — ключі збережених параметрів; перейменування потребує
явного перенесення даних. Невідомі типи/поля й несумісні значення залишаються у сцені
та блокують запуск із діагностикою. Числові межі обмежують ефективне значення у Player;
збережені поля не переписуються під час Play. Integer зберігає всі 64 біти.

EntityRef та AssetRef містять поле `id`; порожній ID означає відсутність посилання.
AssetRef у M5 підтримує модель та її mesh/material/texture. Залежність завантажується
навіть без екземпляра моделі у сцені. Відсутнє посилання, включно зі значенням за
замовчуванням у схемі, блокує Play. Довільні текстові UUID не трактуються як посилання.

## Життєвий цикл та контекст

- OnStart викликається один раз для активного екземпляра.
- OnUpdate отримує dt у секундах. Є KeyDown та KeyPressed для WASD/QE, стрілок,
  Space, Shift, Escape.
- OnStop викликається у зворотному порядку при звичайному завершенні.
- GetTransform / SetTransform працюють із локальною трансформацією.
  Quat у SDK має порядок `w, x, y, z`; одиничний quaternion створюється за замовчуванням.
- GetWorldPosition повертає актуальну світову позицію. Записи трансформацій групуються
  до кінця кадру або наступного запиту світової позиції.
- Get/SetPointLight та Get/SetDirectionalLight змінюють існуючі компоненти освітлення.
- Log записує повідомлення в журнал Player. Збережіть короткі повідомлення;
  безперервний потік обмежується, щоб не блокувати редактор.

Неактивні об'єкти, їхні нащадки та вимкнені прив'язки не виконують callbacks.
Редактор і режим `--describe-behaviors` викликають лише явну реєстрацію.
Вона має описувати типи, не виконувати ігровий код.

## Межі M5

Збірка фіксує вміст усіх підтримуваних файлів Code, версію SDK, компілятор і прапорці.
Підтримуються .cpp/.cc/.cxx та .h/.hh/.hpp/.hxx/.inl/.ipp/.tcc/.inc.
Додаткові include-файли тримайте всередині Code. Користувацькі CMake-скрипти
та C++ modules у цьому етапі не виконуються.

Play створює приватний snapshot у `.proto/snapshots`, а підготовлені моделі з поточними
матеріалами — у спільному `.proto/play-cache`. Поки Player працює, ці файли захищені
від запису/видалення. Player не імпортує glTF, не відкриває авторську сцену та не
потребує ImGui. Редактор призупиняє свій 3D-рендеринг і залишає журнал та Stop.
CPU та RAM редактора і Player відображаються окремо; CPU у відсотках одного ядра.

Stop спочатку надсилає подію завершення. Через 1,5 с завислий процес і його дочірні
процеси примусово завершуються. Аварійний C++ код може не виконати OnStop.
Окремий процес захищає стан редактора від звичайного збою, але не є sandbox
для довільних дій користувацького коду з файлами чи мережею.

Після Stop зберігаються сцена редактора, незбережені правки, вибір та Undo/Redo.
Помилка компіляції або describe не запускає старий executable замість нового.
Самостійне пакування програми з ресурсами, additionalAssets і графічними
налаштуваннями належить до наступного етапу M6.

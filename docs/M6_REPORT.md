# M6 — самостійна програма та графіка Player

Завершено **2026-09-09**. Повний прогін M0–M6: **30/30 Debug**, **30/30 Release**.
Графічна основа — Vulkan 1.3. Готовий приклад:
`examples/ProtoStandalone/Build/Proto Standalone/Proto Standalone.exe`.
[Посібник запуску й експорту](M6_GUIDE.md).

## Результат

У редакторі працює **Експорт .exe**, журнал, скасування та відкриття папки
результату. Експорт компілює збережений C++ і пакує збережену стартову сцену,
її залежності та явні `build.additionalAssets`. Повторний експорт зберігає
попередню версію; помилка чи скасування не видає старий результат за новий.

Готова програма знаходить `Data/runtime.json` біля свого `.exe`, перевіряє
інвентар і SHA-256 та завантажує portable model/data blobs. У форматі немає
C++ padding чи авторських абсолютних шляхів. Спільні raw-дані ділять буфер,
а `BehaviorContext::GetAssetBytes` читає вже завантажені байти.

**F1** відкриває нативні налаштування Player: Low/Balanced/High/Custom,
масштаб рендерингу, VSync, дальність, окремі параметри тіней сонця й точкових
ламп, бюджет point-shadow pool та mip-рівні текстур. Apply/Cancel працюють;
параметри користувача живуть окремо від початкової конфігурації пакета.
Налаштування записуються після успішної підготовки обох кадрових слотів
і потрібних uploads. При невдалому Apply відновлюються попередні параметри.

## Перевірки

| Прогін | Результат | Час |
| --- | --- | --- |
| Повний Debug M0–M6 | 30/30 | 192,96 с |
| Повний Release M0–M6 | 30/30 | 153,23 с |

Джерела: [Debug CTest](research/m6-ctest-debug.xml),
[Release CTest](research/m6-ctest-release.xml), [зведення JSON](research/m6-summary.json).

Шість нових CTest-сценаріїв перевіряють:

- Portable model roundtrip, некоректні діапазони, UUID, дерево BVH й текстури.
- Формат графіки, профілі та коректну projection range для великої near plane.
- Пакування, PE/DLL imports, українські довгі назви, raw UUID при rename/relocation,
  старий session, помилкову C++-схему, source conflict, compile failure і cancel.
- Поточні material overrides, залежності, спільні raw-буфери, читання через
  справжній OnStart, пошкоджені/missing blobs, SDK mismatch, зайві/пропущені файли,
  mutable user settings, private Play і утримання живої папки від заміни.
- Натискання кнопки експорту в ImGui, відмову для незбереженої сцени, призупинення
  3D-редактора, незмінність авторської сцени та збереження попередньої збірки при Stop.
- Запуск перенесеної папки з іншого working directory та PATH лише Windows/System32:
  raw payload, Spin, MoveLight, keyboard input, GPU кадр, F1 Apply/Cancel,
  перезапуск із власною графікою, Low/High/Custom і незмінність packaged defaults.

У статичній сцені з текстурною MASK перевірено чотири збої Apply: до upload,
після записаного upload, на другому кадровому слоті й після lighting commands.
Усі завершилися rollback, наступна спроба відновила рендеринг. На цьому драйвері
swapchain має три зображення; тест робить більше невдалих спроб, ніж їх кількість.
Для інших image counts кількість спроб обчислюється динамічно.
**Core + synchronization validation: 0 errors.**

Повні прогони також повторили M3 oracle для тіней, MASK і batching, M4
save/undo/file transactions та M5 Play/Stop, аварійне завершення й повторний запуск.
Це перевірка поведінки; вона не підмінює майбутній performance benchmark.

## Підтверджені зміни графіки

У тестовому вікні 1375×900 фактичний розмір render target становив:

| Налаштування | Render target | Sun / point resolution | Texture mip drop |
| --- | --- | --- | --- |
| Low | 1031×675 | 1024 / 256 | 1 |
| High | 1375×900 | 2048 / 1024 | 0 |
| Custom, scale 0.5 | 687×450 | 2048 / 1024 | 0 |

Обидва незалежні пули тіней були активні; point pool не перевищував заданого
бюджету. Custom із VSync off обрав `VK_PRESENT_MODE_IMMEDIATE_KHR` на цьому ПК.
На драйвері без такого режиму дозволено FIFO fallback. Метрики ресурсів —
облік виділених renderer/VMA ресурсів, не вимірювання фізичної VRAM.

## Готовий приклад

Папка Proto Standalone містить **51 файл, 5 973 281 байт**. Її PE imports
обмежені системними DLL Windows; додаткових runtime DLL для цього прикладу
копіювати не знадобилося. Vulkan завантажується через системний драйвер.
Компілятор, редактор та Python для запуску пакета не потрібні.

Саме видана папка додатково виконала 90 кадрів із фіксованим dt, керуванням,
чотирма поведінками та GPU validation. Процес завершився з кодом 0;
raw payload прочитано, отримано 0 validation errors.
[Звіт запуску](research/m6-standalone.json), [контрольний кадр](research/m6-standalone.png).

Початкові бінарні файли M5 Debug/Release збережено; їхні SHA-256 збігаються
зі знімком перед M6. Нові збірки й SDK розміщені тільки в `build/m6-*`.
Реалізацію виконано з Luna/max, перевірку — Astra/max; усі підтверджені
матеріальні зауваження виправлено. Фінальна перевірка шляхів, atomic-save,
показу активної графіки та recovery не знайшла нових матеріальних проблем.

## Межі

- Перевірено цей ПК та локальне перенесення/обмежене оточення процесу.
  Чистий другий Windows-комп'ютер не перевірявся.
- Потрібні Windows x64 і сумісний драйвер Vulkan 1.3. Debug validation є
  діагностичною опцією, звичайна програма її не вимагає.
- Растрові тіні мають дискретність і залежать від resolution/filter/bias.
  На пологій площині за нижчої якості може бути помітна квантизація PCF.
  Пряме pixel-порівняння якості потребує однакових позицій та параметрів.
- M7 із навантаженнями 1 000/10 000 instances, багатьма лампами та вимірюваннями
  CPU/GPU/пам'яті ще не виконаний. M6 не обіцяє певного FPS на слабкому залізі.

# Proto Engine

Невеликий 3D-рушій на C++ із редактором та окремими проєктами.
**v0.1 / M8:** наскрізне приймання та готовий комплект редактора, SDK і проєктів.
Експорт самостійної програми та графіка Player через F1.
C++ SDK, класи поведінок, компіляція проєкту та Play/Stop.
Окремі проєкти, файловий браузер, Undo/Redo файлів
та матеріалів, 3D-маніпулятори. Vulkan 1.3 підтримує PBR, glTF/GLB, сонце
й точкові лампи з динамічними тінями. [Початок роботи v0.1](docs/M8_GUIDE.md),
[звіт приймання](docs/M8_REPORT.md).
[Звіт M7](docs/M7_REPORT.md) містить усі порівняння та обмеження; загального
прискорення GPU або фіксованого FPS для довільних сцен не обіцяємо.

## Запуск

Готова програма для Windows x64: [завантажити реліз v0.1](https://github.com/viktor1306/ProtoEngine/releases/tag/v0.1.0).
Розпакуйте `ProtoEngine-v0.1-Windows-x64.zip` і відкрийте `Launch-Demo.cmd`
або `Launch-Player.cmd` усередині папки. SHA-256 архіву наведено в `SHA256SUMS.txt`.
Editor і Player потребують драйвера Vulkan 1.3. SDK в архіві зібраний GCC 16.2.0;
для C++-розробки на іншому ПК зберіть SDK локально командами нижче.

При клонуванні GitHub-репозиторію готових `.exe` та кешу немає: вони доступні
в релізі. Спочатку виконайте локальну збірку з розділу «Збірка».
Демопроєкт із вихідним C++-кодом: [ProtoM8Demo](examples/ProtoM8Demo/README.md).

Відкрийте `Launch-Editor.cmd` у корені проєкту. Він запускає готову Release-
збірку M8, а за її відсутності — Debug. Також можна відкрити
`build/m8-release/bin/ProtoEditor.exe` безпосередньо. Попередні збірки збережено.

Локально сформований комплект: `dist/ProtoEngine-v0.1` (на GitHub — в архіві релізу).
`Launch-Demo.cmd` усередині комплекту відкриває демопроєкт у редакторі,
`Launch-Player.cmd` запускає готову програму. `Templates/ProtoCppEmpty` створює
новий C++-проєкт із власними UUID. Для передавання програми достатньо всієї папки `Player`.

**Файл → Новий проєкт…**: оберіть батьківську папку й назву нового проєкту.
**Файл → Відкрити проєкт…** відкриває його папку. Готовий приклад:
[Proto Playground з C++](examples/ProtoPlayground/Launch-Playground.cmd).
Самостійний приклад: [Proto Standalone](examples/ProtoStandalone/Launch-Standalone.cmd).
Після збереження натисніть **Експорт .exe**; результат — у `Build/<назва проєкту>`.
Після локального експорту: `examples/ProtoStandalone/Build/Proto Standalone/Proto Standalone.exe`.
Переносіть усю папку збірки. **F1** у Player відкриває графіку.
[Інструкція M6](docs/M6_GUIDE.md).
Щоб готовий Player отримав поточний runtime, повторіть **Експорт .exe** у редакторі M8.
Збережений приклад Proto Standalone містить попередню збірку M6.
Проєкт містить `project.proto.json`, `Assets`, `Scenes`, `Code`, `Config` і `.proto`.
Переносіть його цілою папкою разом із `.meta`; кеш у `.proto` відбудовується.

Приклад динамічного світла:
[examples/LightingLab/Launch-LightingLab.cmd](examples/LightingLab/Launch-LightingLab.cmd).
Оберіть теплу або блакитну лампу та перетягніть поле позиції в інспекторі —
тіні змінюються під час руху. Для сонця змінюйте обертання.

Приклад із керамікою, золотом і міддю:
[examples/MaterialLab/Launch-MaterialLab.cmd](examples/MaterialLab/Launch-MaterialLab.cmd).
Чотири сфери використовують одну геометрію та різні матеріальні слоти.

Нова сцена містить куб, площину, камеру й сонце. Готовий старий приклад M1 —
[examples/Starter.scene.json](examples/Starter.scene.json): відкрийте його через
**Файл → Відкрити сцену**. Панелі можна перетягувати за вкладки та змінювати
їхні розміри; розташування зберігається між запусками.

| Дія | Керування |
| --- | --- |
| Вибрати об’єкт | ЛКМ у 3D-вікні або в ієрархії |
| Оглянути сцену | Утримувати ПКМ і рухати мишу |
| Перемістити погляд | СКМ або ПКМ + WASD / Q / E; Shift прискорює |
| Наблизити / віддалити | Колесо миші |
| Фокус на об’єкті | F |
| Змінити позицію, обертання, масштаб | Поля інспектора; Ctrl+клік для точного введення |
| Маніпулятори у 3D-вікні | W — переміщення, E — обертання, R — масштаб; або кнопки над сценою |
| Скасувати поточне перетягування | Escape; один завершений drag — одна Undo-команда |
| Створити об’єкт | Меню «Додати» |
| Змінити батька | Перетягнути вузол в ієрархії або вибрати батька в інспекторі |
| Скасувати / повторити | Ctrl+Z / Ctrl+Y |
| Зберегти / зберегти як | Ctrl+S / Ctrl+Shift+S |
| Відкрити C++ код | Подвійний клік на файлі в папці Code |
| Зберегти код | Кнопка у панелі C++ або Ctrl+S, коли панель активна |
| Зібрати класи поведінок | «Зібрати C++»; діагностики відкривають файл і рядок |
| Запустити / зупинити проєкт | Play / Stop над сценою; Escape у вікні Player |
| Нова / відкрити сцену | Ctrl+N / Ctrl+O |
| Імпортувати модель | «Імпорт glTF / GLB…» у нижній панелі; спочатку збережіть сцену |
| Додати модель із проєкту | Перетягнути glTF/GLB у 3D-вікно або двічі клацнути файл |
| Копіювати / вирізати / вставити файли | Ctrl+C / Ctrl+X / Ctrl+V у нижній панелі; або контекстне меню |
| Перейменувати файл чи папку | F2; «Копіювати як…» створює копію з іншою назвою |
| Перемістити / скопіювати до папки | Перетягнути на папку або ланку шляху; Ctrl — копія |
| Вибрати кілька файлів | Ctrl+клік; Ctrl+A — усі звичайні елементи папки |
| Змінити матеріал | Оберіть mesh → прокрутіть інспектор до «Матеріал» |
| Додати сонце / точкову лампу | Меню «Додати» |
| Вибрати світло | Позначка у 3D-вікні або вузол в ієрархії |
| Якість, дальність та пам'ять тіней | «Вигляд → Налаштування освітлення» → «Застосувати» |
| Відкидання / приймання тіней | Прапорці геометрії в інспекторі |
| Оновити імпорт | Зміни в папці проєкту виявляються автоматично; кнопка «Оновити» для явної перевірки |

При зміні батька зберігається світова трансформація. Якщо потрібен shear або
батько має вироджений масштаб, редактор пропонує зберегти локальні параметри
чи скасувати дію. Перед заміною або закриттям незбереженої сцени є вибір дії.
Переміщення зберігає UUID; копія отримує нові UUID ресурсів зі збереженням
зовнішніх посилань. Undo/Redo перевіряє, чи файли не змінилися зовні, до запису.
Історія файлів і спільних матеріалів живе до закриття проєкту та зберігається
при переході між сценами. Історія об'єктів належить поточній сцені.
Резервні версії файлів зберігаються на диску, ліміт історії — 512 команд / 64 MiB RAM.

## Збірка

Потрібні Windows x64, GCC із C++20, CMake ≥ 3.28, Ninja та драйвер Vulkan 1.3.
На цьому ПК використовується вже встановлений w64devkit; Python не потрібний.

```powershell
# Звичайна збірка й перевірка
powershell -ExecutionPolicy Bypass -File scripts/Build.ps1 -Configuration m8-release -Test

# Debug із локальним validation layer
powershell -ExecutionPolicy Bypass -File scripts/Build.ps1 -Configuration m8-debug -Test
```

Перший configure отримує залежності за commit і SHA-256 у `.cache/`.
Для Debug скрипт окремо готує validation layer. Докладніше про обсяг
завантаження й інструменти — у [звіті M0](docs/M0_REPORT.md), поточні перевірки —
у [звіті M8](docs/M8_REPORT.md). [Команди benchmark](docs/M7_GUIDE.md).
Спільний кеш залежностей захищено від повторного
розпакування під час налаштування іншої конфігурації.

Для v0.1 погоджені glTF/GLB, PBR opaque/mask, ієрархія сцени, динамічні тіні
сонця й точкових ламп, C++-поведінка, ізольований Play/Stop та Undo/Redo.

Студійне освітлення M2 доступне як окремий режим перегляду матеріалів.
M3 використовує справжні карти глибини з поточної геометрії. Менший pool збільшує
кількість пакетів, а не вимикає зайві лампи. Він економить пам'ять ціною додаткових
проходів; конкретний масштаб і швидкодія описані у звіті. Вбудовані куб і площина
також мають освітлення та тіні. Наступний етап — **M6: пакування самостійної програми**.
